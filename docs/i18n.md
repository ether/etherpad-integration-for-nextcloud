# I18N / Translations

## Status

- Admin settings UI text uses Nextcloud L10N (`IL10N->t(...)` / `t(app, key)`).
- The `+ New` entry label (`New pad`) is localized.
- The template tiles are not: the picker labels a tile with its file name, and
  a template is a file. The same applies to every template, including the ones
  richdocuments ships. What a tile *asks* can be translated — the external
  tile's template field carries a translated label.
- Translations are managed on [translatewiki.net][tw], in the Etherpad
  project group, next to Etherpad itself and its plugins.
- Seeded locales: `de`, `es`, `fr`, `it`. `de` and `it` were reviewed
  end-to-end by native speakers; `es` and `fr` are first-pass translations.

[tw]: https://translatewiki.net/

## How it fits together

```
lib/ templates/ src/ appinfo/info.xml
        │  scripts/l10n.sh pot        (xgettext via the Nextcloud translationtool)
        ▼
translationfiles/templates/etherpad_nextcloud.pot     ← translatewiki.net reads this
        │
        ▼  translators work on translatewiki.net
translationfiles/<lang>/etherpad_nextcloud.po         ← translatewiki.net commits these
        │  scripts/l10n.sh convert    (translationtool convert-po-files)
        ▼
l10n/<lang>.json   read by PHP via IL10N
l10n/<lang>.js     read by the frontend via OC.L10N.register
```

`scripts/l10n.sh` wraps the official Nextcloud
[`translationtool`](https://github.com/nextcloud/docker-ci/tree/master/translations/translationtool),
pinned to a commit and checked against a SHA-256, so the app follows the same
extraction rules and output format as every Nextcloud app. It needs `php`
and GNU gettext (`xgettext`, `msgfmt`) on the `PATH`.

The English source strings are the msgids; there is no `en` catalog.
`<lang>` is a Nextcloud locale code (`de`, `pt_BR`, `zh_CN`, …); translatewiki.net
maps its own codes onto them.

`de_DE` is not maintained as a separate file — Nextcloud's locale fallback
maps `de_DE` users to `de.json` automatically. The DE catalog uses Du
throughout.

## Translators

Translate on [translatewiki.net][tw]: create an account, then pick
*Etherpad* → *Etherpad Integration for Nextcloud*. Do not open pull requests
against `l10n/` or `translationfiles/<lang>/`; they are overwritten by the
next translatewiki.net export.

## Developers

- Wrap every user-visible string in `$this->l10n->t('…')` (PHP),
  `$l->t('…')` (templates) or `t(APP_ID, '…')` (JS, from
  `src/lib/oc-compat.js`). The second argument of a JS `t()` call must be a
  string literal, or xgettext cannot see it.
- Use placeholders (`{name}`) instead of concatenating, so translators can
  move them.
- Give translators context where a string is ambiguous with a comment that
  starts with `TRANSLATORS` on the line above the call:

  ```php
  // TRANSLATORS: "Pad" is an Etherpad document, not a notepad
  $this->l10n->t('Open pad');
  ```

  It ends up as a `#.` comment in the template, which translatewiki.net shows
  next to the message.
- After adding, changing or removing a string, run `scripts/l10n.sh pot` and
  commit `translationfiles/templates/etherpad_nextcloud.pot` with the change.
  Changing a string's English text makes it a new message; existing
  translations of the old text are dropped.
- Never edit `l10n/` by hand. It is the output of `scripts/l10n.sh convert`.

The `l10n` workflow runs `scripts/l10n.sh check` on every pull request: it
fails if the template is out of date with the code or `l10n/` is out of date
with the `.po` files.

## Maintainers

translatewiki.net exports to `main` about twice a week, committing as
`translatewiki.net <l10n-bot@translatewiki.net>` with the message
"Localisation updates from https://translatewiki.net.". Its commits only touch
`translationfiles/<lang>/etherpad_nextcloud.po`.

The `l10n sync` workflow then rebuilds `l10n/` from those files and opens
(or refreshes) a pull request from `l10n/translatewiki-sync`. Review it like
any other change: the diff is the new and changed translations. It can also
be started by hand from the Actions tab.

To do the same locally:

```sh
git pull
scripts/l10n.sh convert
git add l10n && git commit -m "chore(l10n): rebuild catalogs from translatewiki.net"
```
